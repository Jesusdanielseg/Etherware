# Glosario de Etherware

| Término                  | Definición en el contexto del proyecto                                                                            |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| API                       | Interfaz que permite que diferentes componentes o sistemas se comuniquen mediante operaciones definidas.           |
| Backend                   | Parte de la aplicación que procesa reglas de negocio, solicitudes y acceso a datos.                               |
| Base de datos             | Conjunto organizado de datos que Etherware almacena y consulta.                                                    |
| Cliente                   | Persona o entidad que solicita o adquiere productos de Fresitas.                                                   |
| Cliente potencial / Lead  | Contacto u oportunidad comercial que puede convertirse en cliente.                                                 |
| Criterio de aceptación   | Condición verificable que debe cumplir una historia de usuario para considerarse aceptada.                        |
| Entrega                   | Proceso mediante el cual un pedido se lleva hasta el destinatario.                                                 |
| Frontend                  | Parte de la aplicación con la que interactúa directamente el usuario.                                            |
| Historia de usuario       | Descripción breve de una necesidad desde la perspectiva de quien utilizará el sistema.                           |
| Inventario                | Registro de productos y de sus existencias y movimientos.                                                          |
| Migración                | Cambio controlado y versionado en la estructura o los datos de una base de datos.                                  |
| Módulo                   | Parte del sistema que agrupa funcionalidades relacionadas.                                                         |
| Product Backlog           | Lista ordenada de necesidades y trabajos que podrían formar parte del producto.                                   |
| Repartidor / Domiciliario | Persona responsable de realizar una entrega.                                                                       |
| Requisito funcional       | Comportamiento o función que el sistema debe ofrecer.                                                             |
| Requisito no funcional    | Condición de calidad o restricción del sistema, como seguridad, rendimiento o usabilidad.                        |
| Scrum                     | Marco de trabajo ágil que organiza el desarrollo en ciclos llamados Sprints y define responsabilidades y eventos. |
| Sprint                    | Periodo de duración fija en el que el equipo crea un incremento de producto.                                      |
| Stakeholder               | Persona o grupo que puede afectar al proyecto, verse afectado por él o tener interés en sus resultados.          |
| Stock                     | Cantidad disponible de un producto en inventario.                                                                  |
| Trazabilidad              | Capacidad de relacionar un requisito con su diseño, implementación y pruebas.                                    |
| Usuario                   | Persona que utiliza Etherware según los permisos que tenga asignados.                                             |
